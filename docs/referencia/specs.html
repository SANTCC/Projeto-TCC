A pasta SPECs

SPECs/ é a fonte primária do projeto: tudo o que o sistema deve fazer, como deve parecer e como o banco é estruturado. Documentação, testes e código devem concordar com ela.

SPECs/
├── Spec.md                      ← especificação funcional (RF, RN, escopo)
├── agents.md                    ← guia de trabalho para agentes/colaboradores
├── tasks.md                     ← decomposição em 9 fases (90 tarefas)
├── backlog.md … backlog4.md     ← correções e melhorias por sessão
├── relatorios-backlog.md        ← relatórios de execução dos backlogs
├── schema.sql                   ← schema completo do banco (574 linhas)
├── design/design.md             ← design system v2.0 (297 linhas)
├── migrations/                  ← migração 001 + README
└── diagnostico/                 ← dois erros reais analisados a fundo

Ele é a fonte de verdade do banco junto com as migrações. Comparações feitas nesta documentação:

6. agents.md — o contrato de trabalho​

195 linhas que definem o que deve e o que não deve ser feito:

RegraConteúdo

utils.jspode crescer, mas cada tela mantém seu próprio <script>

Backlogtoda mudança passa por item de backlog, com relatório de execução

7. tasks.md — 9 fases, 90 tarefas​

Todas as tarefas estão marcadas como concluídas ([x]). A decomposição completa, com dependências e o glossário de códigos, está em Tarefas e fases.

8. Como usar a pasta​

Se você precisa…Vá para
saber o que o sistema deve fazerSpec.md (RF)
saber o que é proibido/permitidoSpec.md (RN) + agents.md
saber como algo deve parecerdesign/design.md + THEME/
saber como o dado é modeladoschema.sql + migrations/
entender um erro de bancodiagnostico/
ver o que mudou e quandobacklog*.md + relatorios-backlog.md
acompanhar a sequência de implementaçãotasks.md
Regra de ouro do repositório

Código que contradiz Spec.md está errado — ou o código, ou a especificação precisa mudar de forma explícita (com item de backlog). Nunca deixe os dois divergirem em silêncio.
